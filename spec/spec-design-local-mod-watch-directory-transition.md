# 背景与目标

macOS CI 两次在逐级创建工坊目录并写入首个 Mod 后超时。用户应能在首次下载完成后看到新安装。

## 1. 范围

调整本地文件监听器处理缺失目录和切换监听路径的逻辑。继续根据文件事件刷新当前游戏的本地库。

## 2. 验收条件

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | Mod 目录或祖先目录尚不存在 | 系统报告正在等待的目录有变化 | 重新确定监听位置并扫描 |
| AC-02 | 目录在确定监听位置后、启用监听时创建 | 新监听器启用 | 重查监听范围，有变化就安排下一次扫描 |
| AC-03 | 其他游戏目录变化或当前工作区取消 | 等待本地安装事件 | 其他游戏事件不触发刷新，取消释放监听器 |

## 3. 责任模块

Infrastructure 的 `FileSystemLocalModMonitor` 已负责路径和事件。处理缺失目录时记录等待的直接子目录。启用监听器后重新检查这些目录，沿用现有队列合并必要的扫描。

## 4. 契约与兼容性

沿用现有监测接口和扫描结果。现有目标继续递归监测，缺失目标继续非递归监测最近的现有父目录。

## 5. 测试策略

复用本地监听集成测试，使用临时路径覆盖逐级创建、快速创建、无关文件和取消。按[协作规范](../CONTRIBUTING.md#4-必须完成的检查)运行检查。

## 6. 审查与执行结果

- [原 CI 的第二次 macOS 26 arm64 日志](https://github.com/zxxwyt/steam-mod-manager-community/actions/runs/43584089320/job/132417733503)显示监听测试在接到空快照后超时。改动前后的监测范围均为当前游戏目录和相关父目录。
- macOS 15.6 arm64 本机执行 Release 还原、构建和全量测试，629 项通过。文件监听测试单独运行 10 轮，每轮 7 项通过。差异检查通过。
- GitHub 托管的三平台检查由修复 PR 运行。
